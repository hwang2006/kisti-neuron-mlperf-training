# NVIDIA A100 Reproduction Notes

## Configuration

The documented A100 reproduction uses:

- GPUs: 8 x NVIDIA A100
- Tensor Parallelism: 4
- Data Parallelism: 2
- Global Batch Size: 32
- Micro Batch Size: 1

Configuration file:

```text
configs/a100/a100_8gpu_tp4_dp2.sh
```

Important runtime settings:

```bash
DISABLE_FP8=1
ENABLE_RECOMPUTE=0
DISABLE_CE_FUSION=0
```

This means FP8 is disabled, activation recomputation is disabled, and
cross-entropy fusion remains enabled for the documented TP4/DP2 reproduction.

The A100-specific runtime code retains optional controls for recomputation and
cross-entropy fusion because they were useful during compatibility and memory
experiments. They are not enabled in the final documented configuration.

---

## Shared Dataset and Tokenizer

The A100 and H200 experiments reuse the same validated preprocessed C4 dataset
and the same Llama 3.1 tokenizer.

Typical paths:

```text
$MLPERF_ROOT/data/C4_processed
$MLPERF_ROOT/models/Llama-3.1-8B
```

A separate full C4 preprocessing step is not required solely because the GPU
generation changes from H200 to A100.

---

## NPY / Dataset Index Cache

The A100 TP4/DP2 experiment uses a separate cache directory:

```text
$MLPERF_ROOT/data/npy_indices/a100_8gpu_tp4_dp2
```

These are runtime document/sample/shuffle mapping caches generated by
Megatron/NeMo and are distinct from the preprocessed C4 `.bin` and `.idx`
files.

---

## Run

After obtaining an allocation with eight A100 GPUs:

```bash
export MLPERF_ROOT=/scratch/$USER/mlperf-training-llama31

cd "$MLPERF_ROOT/kisti-neuron-mlperf-training"

./scripts/run_a100_tp4_dp2.sh
```

## Dataset Scope

The historical A100 runner used:

```text
--use_last_256_shards
```

This selects the consolidated datasets corresponding to the final 256 raw C4
shards:

```text
c4-train.en_6
c4-train.en_7
```

This was used historically as a preliminary end-to-end reproduction and
validation mode before the full-dataset benchmark configuration became the default.

Therefore the historical result is a preliminary/reproduction result and is
not presented as an official full-dataset MLPerf submission.

---

## Relationship to H200 Reproduction

The A100 and H200 paths intentionally share:

- the same pinned MLCommons Training source
- the same Llama 3.1 8B workload
- the same preprocessed C4 dataset
- the same tokenizer
- the same Singularity-based KISTI execution environment
- the same full-dataset default, with optional last-256-shard validation mode

Hardware-specific configuration and runtime controls are kept in separate
files so that results and future changes remain traceable.
